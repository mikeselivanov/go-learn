# Обёртка ошибок контекстом (`fmt.Errorf` + `%w`)

Анализ всех точек обработки ошибок в проекте (`main.go`, `mascot/`, `utils/`).
В `mascot/` и `utils/bin_search.go` ошибок нет вообще (нет функций, возвращающих `error`),
поэтому все находки — из `main.go`, единственного файла с error-хендлингом.

Во всём проекте нашлась только одна точка, где ошибка реально принимается (`err != nil`) —
`main.go:32`. Остальная строка (`main.go:73`) добавлена в таблицу отдельно, так как она тоже
создаёт `error`, но не через оборачивание внешней ошибки (в самой функции нет "исходного" `err`,
который можно было бы обернуть через `%w`) — тем не менее у неё есть смежная проблема:
вызывающий код не может программно отличить "not found" от прочих ошибок.

| Файл | Строка | Текущий код | Предложение |
|---|---|---|---|
| `main.go` | 31–34 | `body, urls, err := fetcher.Fetch(url)`<br>`if err != nil {`<br>`    fmt.Printf("fetch %s: %v\n", url, err)`<br>`    return`<br>`}` | Ошибка не оборачивается и не возвращается — она "теряется" внутри `Crawl` (функция ничего не возвращает). Вызывающий код (`main`) никогда не узнаёт, что часть страниц не была обойдена. Предложение: изменить сигнатуру `Crawl` на `func Crawl(url string, depth int, fetcher Fetcher, cache *UrlCache) error` и оборачивать ошибку контекстом перед возвратом: `return fmt.Errorf("crawl %s: %w", url, err)`. Для параллельных рекурсивных вызовов внутри `wg.Go(...)` ошибки нужно будет собирать (например, через `golang.org/x/sync/errgroup` вместо `sync.WaitGroup`), а `main()` — логировать итоговую ошибку. |
| `main.go` | 73 | `return "", nil, fmt.Errorf("not found: %s", url)` | Это не пропагация чужой ошибки (обёртывать через `%w` нечего — это точка зарождения ошибки), но у неё смежная проблема: строка `"not found: %s"` — обычная строковая ошибка, вызывающий код не может отличить её от других ошибок `Fetch` через `errors.Is`. Предложение: завести сентинел `var ErrNotFound = errors.New("not found")` и возвращать `fmt.Errorf("fetch %s: %w", url, ErrNotFound)` — тогда контекст (какой URL) сохраняется, а тип ошибки остаётся проверяемым через `errors.Is(err, ErrNotFound)`. |

## Итог

- Реальных случаев "голого" `return err` без какого-либо контекста в проекте не найдено —
  единственный `if err != nil` (main.go:32) вообще не пробрасывает ошибку дальше, а глушит её
  через `fmt.Printf`, что хуже, чем отсутствие `%w`-обёртки.
- Правки не применялись — это только анализ, изменения в код не вносились.
